# DECISIONS.md — judgment calls the docs didn't cover

Running log, per the working agreement. None of these conflict with the Five Laws; where a law was adjacent, the law won.

1. **Strategic Analysis file absent from the folder.** Only `Project_Context` and `Recruiting_Platform_User_Flow.md` exist here (the Strategic Analysis is summarized inside Project_Context §11.E). Built against the User Flow doc as spec-of-record + Project_Context; friction F-numbers referenced from the summaries.
2. **Two HS class-of-2029 discoveries added** (Freya Nilsen, Simone Baptiste), making the HS split 16 × ’27/’28 + 2 × ’29. Reason: the spec asks for "some pre-contact-gate" recruits AND all HS recruits in ’27/’28 — but on the demo date (Jul 6, 2026) the June 15 contact window has already passed for both ’27 and ’28. Rather than fake a compliance state, two ’29 discoveries carry the honest "⚠ evaluation only — contact opens Jun 15, 2027" badge.
3. **One 12-metric set across all positions** (subset of the 36-column Wyscout DM-Template schema). Templates differ per position in *values and coach weights*, not in which metrics exist — a prototype simplification (a real GK template wouldn't carry duel-win %). Weights ≥3 drive which bars render by default.
4. **Demo world clock is fixed at Jul 6, 2026** (`NOW` in `store.ts`) so gates, "last updated" stamps, and the calendar stay coherent across test sessions.
5. **Deterministic seeded PRNG** (mulberry32, fixed seed) generates stats and rating trajectories — every "Reset demo data" reproduces byte-identical data, consistent with "every AI behavior simulated deterministically." Percentage metrics clamp to 20–94.
6. **Independent staff ratings on the comparison canvas** are deterministic seeded values (hash of person × staff member), hidden behind a "Reveal" toggle to demonstrate independent-then-reveal. A real build would collect them; the prototype demonstrates the reveal mechanic and the attributed dot-plot.
7. **Device frames guard rather than hide.** Selecting a desktop-only surface on iPad/phone shows an explanation screen ("a deliberate absence, not a missing feature") instead of removing it silently — didactic for moderated testing. Each device also has its own landing surface (desktop→board, iPad→capture, phone→queue).
8. **Tier ids stay color-words** (blue/green/yellow/red) as stable identifiers; display names and colors are editable in Program Setup, echoing Sakuda's whiteboard inheritance.
9. **Exports are simulated** (.xlsx from Sheet View, CSV from the outbox, Wyscout report open) with confirmation toasts — local-only constraint; the affordances are what's being tested.
10. **Role enforcement is displayed, not enforced.** Staff roles (full / capture-only / read-only) render in Setup and on the user switcher, but the prototype doesn't block a capture-only user from re-tiering — moderated tests run as Dana (full access). Noted as a known simplification.
11. **Sideline captures auto-queue compliance "Evaluation" events** (one per saved capture modality). Slight over-counting vs. one-per-viewing is acceptable for the demo and keeps the Law-3 ripple visible.
12. **Merge behavior on approve-duplicate** attaches the new video link to the existing record and logs to the feed; it does not attempt field-level merge UI (out of prototype scope).
13. **Women's program named "Cascadia State University"** per the seed spec; the recruiting lead keeps the first name "Dana" from the user-flow actor table. All player/staff/club names are invented; clubs use plausible-but-fictional Pacific-NW naming.
14. **Deliberate absences honored:** no radar/spider charts, no composite scores, no fit indexes, no AI-confidence meters anywhere — including places a chart library would make them easy.
15. **Program Primer lives inside the Journal screen** (toggle) rather than as a separate nav item — it's assembled *from* journal + setup artifacts, and Flow 12 frames it as an artifact, not a workspace.

## Pitch planner (added Jul 7)

16. **IA placement:** the Athletic-style pitch view lives inside Compare + Depth as the *default* depth view (grid remains a toggle) — it's another lens over the same depth data (Law 3), and Law 4 already anchors roster context there. It shares the same draft-placement state and saved snapshots as the grid, so scenarios built in either view are identical objects.
17. **"Will this make the composition better?" is answered by the coach, not the tool** (Law 1). The machine renders *shape*: presence per season, eligibility runway, attributed criteria reads, and count/sum deltas ("runway 1 → 5"). It never produces a composition score, ranking, or verdict; microcopy on the view says so explicitly.
18. **Short-term vs long-term fit = the season scrubber**, not a computed label. Availability spans: roster players until their class year; transfers arrive now for their parsed eligibility ("N yrs elig."); HS recruits arrive in their class-year fall for 4 years; JuCo for 2. A placed HS ’27 recruit ghosts ("arrives 2027–28") in the current-season view and lands with +4 next season — the coach *sees* the trade-off instead of being told it.
19. **Replace-vs-strengthen is coach-declared, not inferred.** Dropping a recruit on a position asks "How does this placement read?" — replaces a named departing player (⇄) or adds depth (+). The intent is stored on the placement and shown on snapshot cards.
20. **Criteria lenses use only attributed human data.** Dimension lenses (Motor / First touch / Compete) read roster players' spring-review entries (coach-entered, seeded with author + date) and recruits' live-capture dims (latest per author). Divergent reads render side by side with author initials and a "divergent" flag — never averaged. Missing data renders as "not yet assessed" (an evaluation gap, not a zero). Metric lenses show the per-90 value with the named template's tick. Coaches can pin up to 3 lenses as this season's focus (★, stored as program metadata).
21. **Mirrored position boxes are display-only.** W/CM/FB/CB groups split alternately across L/R boxes to echo the whiteboard/Athletic layout; our position taxonomy has no left/right distinction and a drop on either box maps to the same group. Drops on the wrong position group are rejected with an explanation ("the pitch reflects, it doesn't reassign").
22. **Persistence key bumped to v2** (`csu-recruiting-proto-v2`) because the Person shape gained `staffDims` — stale v1 state is ignored rather than migrated.

## Insights surface (added Jul 15)

23. **A dedicated Insights screen was added (desktop-only) — and it does NOT reopen the "deliberate absences" (#14, Law 1).** The test for every element here is: does it produce a *verdict on a player* (score, rank, fit-index, "you should…")? If yes, it's out. All four lenses render **shape and coverage over human-entered counts**, never a quality signal:
    - **Board at a glance** — distribution of the 28 recruits across tier / pipeline / class year / position. Pure composition counts.
    - **Position coverage vs graduation** — roster returning vs graduating (hollow rings) laid beside board depth per position (Law 4). Never a computed "need score"; the gap is shown, the read is the coach's (mirrors pitch-planner stance #17).
    - **Evaluation coverage / gaps** — sorts recruits by *how often the staff has watched*, surfacing "not yet assessed" and video-chase gaps. This is the inverse of a ranking: it shows where you **haven't** looked, not who's best. Reuses the existing attributed rating sparkline.
    - **Staff activity over time** — captures & contacts per staff, attributed and time-bucketed (Law 5). Ordered by role, not volume — coverage, not a leaderboard.
    Each section carries a visible italic law-note stating what it does and doesn't claim. No new data model; all derived from `people` / `captures` / `contactLogs`.
